# Command-line usage

```text
aics [OPTIONS] [QUERY]
```

`QUERY` is optional. In interactive mode it runs the initial search and remains
in the TUI search field. With `--json`, it selects the search results written as
JSONL. Rules modes do not accept a text query.

Run `aics --help` for the compact reference generated by the current binary.

## Common examples

```bash
# Open the TUI for sessions associated with the current directory
aics

# Search all indexed sessions
aics -g

# Start with a query in the TUI
aics -g "vector db"

# Search one agent within a date range
aics -g --agent claude --after 2026-03-01 --before 2026-03-31 deploy

# Write relevance-sorted results as JSONL
aics --json -g --sort-by relevance "vector db"

# Review cleanup-rule proposals without changing session files
aics --preview-rules -g

# Print cleanup-rule proposals as JSONL
aics --preview-rules --json -g
```

## Scope and query

| Option | Meaning |
| --- | --- |
| `QUERY` | Optional initial search query |
| `-g`, `--global` | Search all indexed sessions |
| `--no-global` | Force project-local startup when the saved TUI default is global |
| `--dir PATH[:BRANCH]` | Search a specific project directory, optionally limited to a branch |
| `--branch BRANCH` | Limit results to a branch |
| `--session SESSIONID` | Select one exact session ID |

Without a scope flag, AICS starts from the current directory. `--no-global`
changes only the startup scope; `Ctrl+G` can still switch between local and
global scope inside the TUI.

`--global` and `--no-global` conflict. A branch supplied by `--branch` must match
one embedded in `--dir PATH:BRANCH`.

See [Search and indexing](search-and-indexing.md) for query syntax, ranking, and
indexed content.

## Result filters

| Option | Meaning |
| --- | --- |
| `-n N`, `--num-results N` | Load or emit at most `N` results; default: `2000`, minimum effective value: `1` |
| `--agent AGENT` | Include only `claude` or `codex` sessions |
| `--after DATE` | Include sessions on or after a date or timestamp |
| `--before DATE` | Include sessions on or before a date or timestamp |
| `--min-lines N` | Require at least `N` content lines |
| `--no-original` | Exclude original/root sessions |
| `--no-trimmed` | Exclude trimmed sessions |
| `--no-rollover` | Exclude continued/rollover sessions |
| `--no-continued` | Alias for `--no-rollover` |
| `--sub-agent` | Include sub-agent or sidechain sessions |
| `--live` | Include only sessions that currently appear live |
| `--trashed MODE` | Select `no`, `yes`, or `both` trashed-session modes; default: `no` |

`--after` and `--before` accept RFC 3339 timestamps or `YYYY-MM-DD`. A bare date
uses the local timezone: `--after` begins at the start of that day and
`--before` ends at 23:59:59.

Sub-agent sessions are excluded unless `--sub-agent` is present.

## Sorting and output

| Option | Meaning |
| --- | --- |
| `--sort-by MODE` | Select `time` or `relevance` ordering; command-line default: `time` |
| `--json` | Write one JSON search hit or rule record per line instead of opening the TUI |
| `--progress STREAM` | Select `none`, `stderr`, or `stdout`; default: `stderr` |

Progress is drawn only when its selected stream is a terminal. `--progress stdout`
conflicts with `--json` because stdout is reserved for JSONL; use the default
stderr progress or `--progress none` in scripts.

Outside rules mode, redirecting or piping a TUI invocation is rejected. Add
`--json` when non-interactive stdout is required.

`--json` changes output mode but does not disable automatic rules configured
with `applyAtStartup: true`. Add `--no-apply-rules` when a JSON search must not
apply startup cleanup actions.

## JavaScript rules modes

| Option | Meaning |
| --- | --- |
| `--preview-rules` | Evaluate all rules and review proposals without applying them |
| `--apply-rules` | Evaluate all rules and apply supported actions non-interactively |
| `--no-apply-rules` | Disable automatic `applyAtStartup` rules during ordinary startup |
| `--rules PATH` | Use another rules file without reading or writing rules caches |
| `--write-rules-dts` | Write `~/.config/aics/rules.d.ts` and exit |

`--preview-rules` opens a review TUI unless combined with `--json`.
`--preview-rules` and `--apply-rules` conflict. Explicit preview/apply modes do
not accept `QUERY` or `--live` and always evaluate every registered rule.
`--no-apply-rules` conflicts with explicit preview/apply modes and with
`--rules PATH`.

`--rules PATH` selects a custom file for explicit rules mode or automatic
startup application. Custom rule files bypass cache reads and writes.

See [JavaScript rules](rules-js.md) for the rules API, actions, startup behavior,
and caching.

## Index and session locations

| Option | Meaning |
| --- | --- |
| `--rebuild-index` | Rebuild the selected index profile, then continue to rules/search |
| `--delete-index` | Delete the selected index profile and exit |
| `--claude-home PATH` | Override the Claude Code home for this run |
| `--codex-home PATH` | Override the Codex CLI home for this run |

`--rebuild-index` and `--delete-index` conflict. Home overrides affect session
discovery and select a cache profile based on the resulting session-root set.

See [Search and indexing](search-and-indexing.md) for default roots, environment
overrides, cache profiles, and incremental indexing.

## Saved TUI defaults

The TUI can save default scope, sorting, and filters. Explicit command-line
options take precedence where the CLI exposes a corresponding override.
`--no-global` exists specifically to override a saved global scope for one
launch.

Saved TUI defaults are applied when entering the TUI. JSON and explicit rules
modes use their command-line scope and filters instead.

## Informational and exit-only options

| Option | Meaning |
| --- | --- |
| `--print-palettes` | Print built-in theme palettes as ANSI color cards and exit |
| `-h`, `--help` | Print command-line help |
| `-V`, `--version` | Print the AICS version |

`--write-rules-dts`, `--delete-index`, and `--print-palettes` exit without
entering the TUI. `--rebuild-index` is different: it rebuilds and then continues
with normal startup.
